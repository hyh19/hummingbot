# 执行策略（Execution Strategies）

## 概述

执行策略专注于如何高效地完成大额交易订单，目标是最小化市场冲击和滑点成本。与追求盈利的交易策略不同，执行策略的核心是以最优的方式执行既定的交易计划。

本文档介绍社区贡献的交易执行策略。

## 策略详解

### simple_vwap_no_config.py

**核心功能**：VWAP 执行策略。通过多次小额订单逐步完成大额交易目标，每次交易使用订单簿累计量的一定百分比，最小化市场冲击。

**适用场景**：适用于需要执行大额订单的场景，通过分批执行降低滑点和价格冲击。

**关键特点**：

- 使用 RateOracle 进行 USD 转换
- 支持设置最大价差和交易间隔时间
- 动态计算每次订单量
- 实时追踪执行进度

## VWAP 策略原理

### 什么是 VWAP？

VWAP（Volume Weighted Average Price，成交量加权平均价格）是一个重要的交易基准：

```text
VWAP = Σ (成交价格 × 成交量) / Σ 成交量
```

**VWAP 的意义**：

- 反映某一时段内的平均成交价格
- 常用于评估交易执行质量
- 机构交易者常用的交易基准

### 策略目标

通过分批执行大额订单，使平均成交价格尽可能接近市场 VWAP：

1. **减少市场冲击**：大额订单一次性成交会显著影响价格
2. **降低滑点**：分批执行可以获得更好的平均价格
3. **隐藏意图**：避免让市场察觉大额交易意图

## 策略配置

### 核心参数

```python
vwap = {
    "connector_name": "binance_paper_trade",  # 交易所
    "trading_pair": "ETH-USDT",               # 交易对
    "is_buy": True,                            # 买入还是卖出
    "total_volume_usd": 10000,                 # 总交易金额（USD）
    "price_spread": 0.001,                     # 最大价差（0.1%）
    "volume_perc": 0.001,                      # 每次交易量百分比（0.1%）
    "order_delay_time": 10                     # 订单间隔时间（秒）
}
```

### 参数说明

1. **total_volume_usd**：
   - 要执行的总交易金额（以 USD 计价）
   - 策略会自动转换为基础资产数量

2. **price_spread**：
   - 相对中间价的最大价差
   - 用于限制订单价格范围
   - 买入：mid_price × (1 + spread)
   - 卖出：mid_price × (1 - spread)

3. **volume_perc**：
   - 每次交易使用订单簿深度的百分比
   - 例如：0.001 表示使用 0.1% 的累计量

4. **order_delay_time**：
   - 两次订单之间的等待时间
   - 避免过于频繁的交易

## 执行流程

### 1. 初始化

```text
获取汇率并计算：
- 目标基础资产数量 = total_volume_usd / base_usd_rate
- 理想计价资产花费 = total_volume_usd / quote_usd_rate

模拟市价单执行：
- 计算如果一次性市价成交需要的成本
- 作为性能对比基准
```

### 2. 计算单次订单量

```text
步骤：
1. 获取当前中间价
2. 应用价差计算限价
3. 查询订单簿，计算到该价位的累计量
4. 取累计量的 volume_perc% 作为本次订单量
5. 取本次订单量和剩余量的较小值
```

### 3. 执行订单

```text
对每个订单：
1. 检查是否超过 order_delay_time
2. 检查余额是否充足
3. 创建并执行市价单
4. 记录成交信息
5. 更新剩余量和已花费金额
```

### 4. 追踪进度

```text
执行进度 = 已完成量 / 目标总量
实际花费 = Σ (成交价格 × 成交量)
平均成交价 = 实际花费 / 已完成量
```

## 使用示例

### 示例 1：买入 10,000 美元的 ETH

```python
vwap = {
    "connector_name": "binance_paper_trade",
    "trading_pair": "ETH-USDT",
    "is_buy": True,
    "total_volume_usd": 10000,
    "price_spread": 0.001,        # 0.1%
    "volume_perc": 0.002,         # 0.2%
    "order_delay_time": 15        # 15 秒
}
```

**执行过程**：

```text
假设 ETH 价格 = 2000 USDT
目标数量 = 10000 / 2000 = 5 ETH

第 1 次：买入 0.1 ETH @ 2000.5 USDT
第 2 次：买入 0.12 ETH @ 2001.0 USDT
第 3 次：买入 0.15 ETH @ 2000.8 USDT
...
直到完成 5 ETH

平均成交价：~2000.7 USDT
总花费：~10003.5 USDT
```

## 性能评估

### 关键指标

1. **平均成交价**：

   ```text
   平均成交价 = 总花费 / 总成交量
   ```

2. **相对 VWAP 的偏差**：

   ```text
   偏差 = (平均成交价 - 市场 VWAP) / 市场 VWAP
   ```

3. **相对市价单的改善**：

   ```text
   改善 = (市价单成本 - 实际成本) / 市价单成本
   ```

4. **完成时间**：

   ```text
   完成时间 = 最后一笔 - 第一笔
   ```

### 性能优化目标

- **买入**：平均成交价 < 期间 VWAP
- **卖出**：平均成交价 > 期间 VWAP
- 市场冲击：< 0.1%
- 完成率：> 95%

## 参数优化

### volume_perc（订单量百分比）

**较大值（0.5% - 1%）**：

- 优点：执行速度快
- 缺点：市场冲击大，可能获得较差价格

**较小值（0.05% - 0.1%）**：

- 优点：市场冲击小，价格更优
- 缺点：执行时间长，可能无法完成

**建议**：

- 流动性好的交易对：0.1% - 0.3%
- 流动性一般的交易对：0.05% - 0.1%

### price_spread（价差限制）

**较大值（0.3% - 0.5%）**：

- 优点：完成率高
- 缺点：可能接受较差的价格

**较小值（0.05% - 0.1%）**：

- 优点：价格更优
- 缺点：可能无法完成全部订单

**建议**：

- 根据交易紧急程度设置
- 不急的订单：0.05% - 0.1%
- 需要快速完成：0.2% - 0.3%

### order_delay_time（订单间隔）

**较长间隔（30 - 60 秒）**：

- 优点：更好地隐藏交易意图
- 缺点：执行时间长，价格可能变化

**较短间隔（5 - 15 秒）**：

- 优点：快速完成
- 缺点：交易模式可能被识别

**建议**：

- 大额订单：20 - 30 秒
- 中等订单：10 - 15 秒
- 小额订单：5 - 10 秒

## 风险管理

### 1. 未完成风险

**原因**：

- 市场流动性不足
- 价格快速变动超出 spread 范围
- 余额不足

**应对**：

- 监控执行进度
- 必要时调整 price_spread
- 准备备用执行方案（如市价单兜底）

### 2. 价格冲击风险

**原因**：

- volume_perc 设置过大
- 订单间隔太短
- 市场流动性突然下降

**应对**：

- 动态调整 volume_perc
- 增加订单间隔
- 避开流动性差的时段

### 3. 市场趋势风险

**原因**：

- 执行期间价格持续上涨（买入）或下跌（卖出）
- 错过更好的执行时机

**应对**：

- 缩短执行时间窗口
- 使用更激进的参数
- 考虑暂停等待更好时机

## 进阶技巧

### 1. 时间加权执行

根据交易时段的特点调整执行速度：

```python
# 流动性高的时段加快执行
if is_peak_hours():
    volume_perc = 0.003  # 更激进
else:
    volume_perc = 0.001  # 更保守
```

### 2. 动态价差调整

根据执行进度动态调整价差：

```python
progress = completed / target
if progress < 0.5:
    # 前半程保守
    price_spread = 0.001
else:
    # 后半程加速完成
    price_spread = 0.002
```

### 3. 订单分组

将大订单拆分为多个小批次：

```python
total = 100 ETH
batches = [20, 25, 30, 25]  # 分 4 批
# 每批之间间隔更长时间
```
