# 套利策略（Arbitrage Strategies）

## 概述

套利策略通过利用不同市场或交易对之间的价格差异来获取无风险或低风险收益。套利机会通常存在时间很短，需要快速执行。相比方向性策略，套利策略的风险较低，但需要更高的资金量和更快的执行速度。

本文档介绍 4 个社区贡献的套利策略，涵盖跨交易所套利、三角套利、现货-合约套利和跨交易所做市等场景。

## 策略列表

### 1. simple_arbitrage_example.py

**核心功能**：跨交易所套利策略。通过比较两个交易所的 VWAP 价格，当价差超过最小盈利阈值时执行套利交易。

**适用场景**：适用于流动性好且存在价格差异的交易对，在不同交易所间捕捉无风险套利机会。

**关键计算**：

- 计算两个交易所的 VWAP（成交量加权平均价格）
- 考虑交易费用后的净利润
- 支持双向套利（买 A 卖 B 或买 B 卖 A）

**策略逻辑**：

1. 获取两个交易所的买卖 VWAP 价格
2. 计算两个方向的套利机会：
   - 方向 A：在交易所 A 买入，在交易所 B 卖出
   - 方向 B：在交易所 B 买入，在交易所 A 卖出
3. 扣除两个交易所的交易费用
4. 如果净利润超过 `min_profitability` 阈值，执行套利

**配置参数**：

- `order_amount`：套利订单数量（基础资产）
- `min_profitability`：最小盈利阈值（百分比）
- `exchange_A`、`exchange_B`：两个交易所
- `trading_pair`：交易对

**盈利计算示例**：

```text
买入价（交易所 A）：100 USDT
卖出价（交易所 B）：101 USDT
交易费用（A）：0.1%
交易费用（B）：0.1%
净利润 = (101 * 0.999 - 100 * 1.001) / 100 = 0.798%
```

**使用建议**：

- 设置合理的最小盈利阈值（至少 3 倍手续费）
- 确保两个交易所都有足够的余额
- 监控两个交易所的延迟和订单执行速度
- 考虑提现和充值的时间和成本

### 2. triangular_arbitrage.py

**核心功能**：三角套利策略，在同一交易所的三个交易对之间寻找套利机会。策略会自动检测并执行有利可图的循环交易路径。

**适用场景**：适用于流动性充足的交易所，通过三角关系中的价格不平衡获利。

**关键特点**：

- 支持正向和反向两种套利方向
- 包含失败重试机制（最多 10 次）
- 止损开关（Kill Switch）防止过度亏损
- 线性执行订单（前一个完成后再执行下一个）

**策略逻辑**：

1. 初始化：检查三个交易对是否适合三角套利
2. 每个 tick 计算两个方向的盈利：
   - 直接方向：卖 A-USDT → 卖 A-BTC → 买 BTC-USDT
   - 反向方向：买 BTC-USDT → 买 A-BTC → 卖 A-USDT
3. 如果盈利超过阈值，执行套利
4. 线性执行三个订单
5. 记录盈亏并检查止损开关

**配置参数**：

- `first_pair`、`second_pair`、`third_pair`：三个交易对
- `holding_asset`：主要持有的资产（如 USDT）
- `min_profitability`：最小盈利阈值（百分比）
- `order_amount_in_holding_asset`：每轮套利的资金量
- `kill_switch_enabled`：是否启用止损开关
- `kill_switch_rate`：止损阈值（累计亏损百分比）

**三角套利示例**：

持有资产：USDT
交易对：ADA-USDT、ADA-BTC、BTC-USDT

直接方向：

1. 买 ADA-USDT（100 USDT → 200 ADA）
2. 卖 ADA-BTC（200 ADA → 0.01 BTC）
3. 卖 BTC-USDT（0.01 BTC → 102 USDT）

利润：2 USDT（2%）

**使用建议**：

- 选择流动性好的交易对组合
- 最小盈利阈值应考虑 3 次交易的总费用
- 启用止损开关防止连续亏损
- 监控订单执行情况，及时处理失败订单

### 3. spot_perp_arb.py

**核心功能**：现货-永续合约套利策略。当现货和合约价格出现显著差异时，同时在两个市场开仓，等待价格收敛后平仓获利。

**适用场景**：适用于同一资产的现货和永续合约市场，捕捉资金费率和价格偏差带来的套利机会。

**关键机制**：

- 使用状态机管理开仓、持仓和平仓流程
- 记录订单簿数据到 CSV 文件
- 支持双向套利（买现货做空合约 / 卖现货做多合约）

**状态机流程**：

1. **Closed（关闭）**：等待套利机会
2. **Opening（开仓中）**：正在执行开仓订单
3. **Opened（已开仓）**：持有套利仓位，等待平仓机会
4. **Closing（平仓中）**：正在执行平仓订单

**套利方向**：

**方向 A - 买现货做空合约**：

- 条件：合约价格 > 现货价格 + 利润阈值
- 操作：买入现货 + 开空合约
- 平仓：卖出现货 + 平空合约

**方向 B - 卖现货做多合约**：

- 条件：现货价格 > 合约价格 + 利润阈值
- 操作：卖出现货 + 开多合约
- 平仓：买入现货 + 平多合约

**配置参数**：

- `spot_connector`：现货交易所
- `perp_connector`：永续合约交易所
- `trading_pair`：交易对
- `leverage`：合约杠杆倍数
- `base_order_amount`：每次套利的数量
- `buy_spot_short_perp_profit_margin_bps`：方向 A 利润阈值（基点）
- `sell_spot_long_perp_profit_margin_bps`：方向 B 利润阈值（基点）
- `slippage_buffer_bps`：滑点缓冲（基点）

**风险控制**：

- 检查持仓时间，超时警告
- 验证余额充足
- 限制在飞行状态的等待时间

**使用建议**：

- 确保现货和合约账户都有足够余额
- 设置合理的利润阈值（考虑资金费率）
- 使用单向持仓模式（One-way Mode）
- 监控持仓时间，避免长期持仓

### 4. simple_xemm_no_config.py

**核心功能**：跨交易所做市策略（Cross-Exchange Market Making）。在做市交易所放置订单，当订单成交后立即在对冲交易所进行反向交易，锁定价差利润。

**适用场景**：适用于流动性不同的交易所之间，通过提供流动性并对冲风险赚取稳定收益。

**关键逻辑**：

- 在流动性较低的交易所（Maker）放置买卖订单
- 订单成交后，立即在流动性较高的交易所（Taker）对冲
- 锁定两个交易所之间的价差

**策略流程**：

1. 获取 Taker 交易所的买卖价格
2. 在 Maker 交易所放置订单：
   - 买单价格 = Taker 卖价 * (1 - spread_bps)
   - 卖单价格 = Taker 买价 * (1 + spread_bps)
3. Maker 订单成交后，立即在 Taker 执行反向对冲
4. 监控价差，如果低于最小阈值则取消订单

**配置参数**：

- `maker_exchange`：做市交易所（流动性较低）
- `taker_exchange`：对冲交易所（流动性较高）
- `order_amount`：订单数量
- `spread_bps`：相对 Taker 价格的价差（基点）
- `min_spread_bps`：最小价差阈值（基点）
- `slippage_buffer_spread_bps`：对冲订单的滑点缓冲（基点）
- `max_order_age`：订单最大存活时间（秒）

**盈利计算**：

```text
Taker 买价：100 USDT
Taker 卖价：100.2 USDT
Spread：10 bps (0.1%)

Maker 买单：100.2 * 0.999 = 100.1 USDT
Maker 卖单：100 * 1.001 = 100.1 USDT

场景 1：Maker 买单成交
- 在 Maker 以 100.1 USDT 买入
- 在 Taker 以 100 USDT 卖出（对冲）
- 利润：视 Taker 实际成交价而定

场景 2：Maker 卖单成交
- 在 Maker 以 100.1 USDT 卖出
- 在 Taker 以 100.2 USDT 买入（对冲）
- 利润：视 Taker 实际成交价而定
```

**订单管理**：

- 订单刷新：价差低于最小阈值或超过最大存活时间
- 对冲执行：使用限价单 + 滑点缓冲，提高成交概率
- 余额检查：确保两个交易所都有足够余额

**使用建议**：

- 选择流动性差异明显的交易所组合
- Spread 设置应大于两个交易所的费用总和
- 设置合理的滑点缓冲以确保对冲成功
- 监控对冲执行情况，避免对冲失败导致风险敞口

## 套利策略通用建议

### 机会识别

1. **价差监控**：持续监控多个市场的价格差异
2. **费用计算**：准确计算所有交易费用、提现费用
3. **执行速度**：套利机会转瞬即逝，需要快速执行
4. **流动性评估**：确保足够的流动性支持订单执行

### 风险管理

1. **余额管理**：在所有涉及的交易所保持足够余额
2. **对冲风险**：确保对冲订单能够及时执行
3. **网络延迟**：考虑网络延迟对套利机会的影响
4. **交易所风险**：分散资金，避免单一交易所风险

### 资金效率

1. **资金配置**：合理分配资金到不同交易所
2. **转账时间**：考虑跨交易所转账的时间成本
3. **机会成本**：评估资金占用的机会成本

### 监控与优化

1. **实时监控**：监控策略执行情况和盈亏
2. **数据记录**：记录所有套利机会和执行结果
3. **参数优化**：根据历史数据优化利润阈值和滑点设置
4. **异常处理**：及时处理订单失败、余额不足等异常
