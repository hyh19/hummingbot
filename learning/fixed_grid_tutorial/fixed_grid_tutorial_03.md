## 3.1 参数概览

Fixed Grid 策略共有 13 个可配置参数，分为必需参数和可选参数两类。

### 3.1.1 参数列表

**必需参数（6 个）**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| `trading_pair` | 字符串 | 交易对 |
| `exchange` | 字符串 | 交易所名称 |
| `n_levels` | 整数 | 网格层级数 |
| `grid_price_ceiling` | Decimal | 网格价格上限 |
| `grid_price_floor` | Decimal | 网格价格下限 |
| `order_amount` | Decimal | 基础订单数量 |

**可选参数（7 个）**：

| 参数名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `spread_scale_factor` | Decimal | 1.0 | 网格间距缩放因子 |
| `amount_scale_factor` | Decimal | 1.0 | 订单数量缩放因子 |
| `rebalance_order_type` | 字符串 | "limit" | 再平衡订单类型 |
| `rebalance_order_spread` | Decimal | 0.02 | 再平衡订单价差（%） |
| `rebalance_order_refresh_time` | 浮点数 | 60.0 | 再平衡订单刷新时间（秒） |
| `grid_orders_refresh_time` | 浮点数 | 3600000.0 | 网格订单刷新时间（秒） |
| `price_source` | PriceType | MidPrice | 参考价格类型 |

## 3.2 必需参数详解

### 3.2.1 trading_pair（交易对）

**定义**：要交易的加密货币对。

**格式**：`基础资产-报价资产`

**代码位置**：

```18:18:scripts/community/fixed_grid.py
trading_pair = "ENJ-USDT"
```

**配置示例**：

```python
trading_pair = "BTC-USDT"   # 比特币/USDT
trading_pair = "ETH-USDC"   # 以太坊/USDC
trading_pair = "SOL-BUSD"   # Solana/BUSD
```

**选择建议**：

1. **流动性**：选择交易量大的交易对
   - 日交易量 > 100 万美元较为理想
   - 订单簿深度好，买卖价差小

2. **波动性**：选择波动适中的交易对
   - 日波动率在 2%-8% 之间
   - 避免暴涨暴跌的极端币种

3. **价格区间稳定性**：
   - 近期有明显的震荡区间
   - 支撑位和阻力位清晰

4. **手续费考虑**：
   - 某些交易所对特定交易对有手续费折扣
   - 考虑使用平台币抵扣手续费

**注意事项**：

- 交易对格式必须与交易所支持的格式一致
- 某些交易所使用 `/` 分隔符（如 `BTC/USDT`），需要查看交易所文档
- 不同交易所对同一交易对的命名可能不同（如 `BTCUSDT` vs `BTC-USDT`）

### 3.2.2 exchange（交易所）

**定义**：执行交易的交易所名称。

**代码位置**：

```19:19:scripts/community/fixed_grid.py
exchange = "ascend_ex"
```

**支持的交易所**：

Hummingbot 支持多家中心化交易所，常见的包括：

- `binance`：币安
- `huobi`：火币
- `okx`：OKX
- `kucoin`：库币
- `gate_io`：Gate.io
- `ascend_ex`：AscendEX

**配置示例**：

```python
exchange = "binance"
exchange = "okx"
exchange = "kucoin"
```

**选择建议**：

1. **手续费率**
   - Maker 费率越低越好（网格策略多为 Maker 订单）
   - 考虑 VIP 等级折扣
   - 某些交易所支持平台币抵扣

2. **API 稳定性**
   - 选择 API 稳定、响应快的交易所
   - 避免频繁 API 错误的平台

3. **流动性**
   - 目标交易对在该交易所的流动性
   - 订单簿深度和价差

4. **提现便利性**
   - 提现手续费和限额
   - 提现到账时间

**手续费对比示例**：

| 交易所 | Maker 费率 | Taker 费率 | 备注 |
|--------|-----------|-----------|------|
| Binance | 0.02% | 0.04% | BNB 可抵扣 25% |
| OKX | 0.08% | 0.10% | OKB 可抵扣 |
| KuCoin | 0.10% | 0.10% | KCS 可抵扣 |

### 3.2.3 n_levels（网格层级数）

**定义**：将价格区间划分为多少层网格。

**类型**：整数，必须为偶数（代码设计要求）

**代码位置**：

```20:20:scripts/community/fixed_grid.py
n_levels = 8
```

**取值范围**：

- **最小值**：4 层（过少无法有效捕捉波动）
- **建议值**：6-20 层
- **最大值**：理论无上限，但过多会占用过多资金

**配置示例**：

```python
n_levels = 6   # 简单配置，适合新手
n_levels = 10  # 均衡配置
n_levels = 20  # 精细配置，需要更多资金
```

**选择建议**：

1. **根据价格区间大小**

```text
区间跨度 = (上限 - 下限) / 下限 × 100%

跨度 < 5%：  6-10 层
跨度 5-10%： 10-15 层
跨度 > 10%： 15-25 层
```

2. **根据资金量**

每增加一层网格，需要的资金会增加。假设每层订单 100 USDT：

```text
8 层：需要约 400 USDT
12 层：需要约 600 USDT
16 层：需要约 800 USDT
```

3. **根据波动频率**

```text
高频波动（日内多次）：更多层级（15-20 层）
中频波动（每天 1-2 次）：适中层级（10-15 层）
低频波动（几天一次）：较少层级（6-10 层）
```

**影响分析**：

| 层级数 | 优点 | 缺点 |
|--------|------|------|
| 少（6-8） | 资金需求小，易管理 | 单次利润大，但交易频率低 |
| 中（10-15） | 平衡收益与资金占用 | 配置相对复杂 |
| 多（16+） | 交易频率高，总收益可能更高 | 资金需求大，单次利润小 |

### 3.2.4 grid_price_ceiling（网格价格上限）

**定义**：网格的最高价格层级。

**类型**：Decimal 类型

**代码位置**：

```21:21:scripts/community/fixed_grid.py
grid_price_ceiling = Decimal(0.33)
```

**配置示例**：

```python
grid_price_ceiling = Decimal(0.35)    # ENJ-USDT
grid_price_ceiling = Decimal(45000)   # BTC-USDT
grid_price_ceiling = Decimal(2800)    # ETH-USDT
```

**设置建议**：

1. **基于技术分析**

- 选择明显的阻力位作为上限
- 参考历史高点和关键价格位
- 考虑心理价位（如整数关口）

2. **基于波动率**

```text
当前价格：P
日均波动率：V

保守型：上限 = P × (1 + V × 1.5)
均衡型：上限 = P × (1 + V × 2.0)
激进型：上限 = P × (1 + V × 3.0)
```

**示例计算**（ENJ 当前价格 0.31 USDT，日波动率 5%）：

```text
保守型：0.31 × (1 + 0.05 × 1.5) = 0.333 USDT
均衡型：0.31 × (1 + 0.05 × 2.0) = 0.341 USDT
激进型：0.31 × (1 + 0.05 × 3.0) = 0.356 USDT
```

3. **与当前价格的关系**

```text
理想情况：当前价格位于网格区间的中部

上限 = 当前价格 × 1.05 到 1.15 之间
```

**风险提示**：

- 上限设置过高：价格难以触及，卖单长期不成交，资金利用率低
- 上限设置过低：价格容易突破，策略失效

### 3.2.5 grid_price_floor（网格价格下限）

**定义**：网格的最低价格层级。

**类型**：Decimal 类型

**代码位置**：

```22:22:scripts/community/fixed_grid.py
grid_price_floor = Decimal(0.3)
```

**配置示例**：

```python
grid_price_floor = Decimal(0.28)     # ENJ-USDT
grid_price_floor = Decimal(40000)    # BTC-USDT
grid_price_floor = Decimal(2400)     # ETH-USDT
```

**设置建议**：

1. **基于技术分析**

- 选择明显的支撑位作为下限
- 参考历史低点和关键价格位
- 考虑心理价位

2. **基于波动率**

```text
当前价格：P
日均波动率：V

保守型：下限 = P × (1 - V × 1.5)
均衡型：下限 = P × (1 - V × 2.0)
激进型：下限 = P × (1 - V × 3.0)
```

3. **与上限的配比**

```text
理想的上下限比例：

保守型：(上限 - 下限) / 下限 = 5-8%
均衡型：(上限 - 下限) / 下限 = 8-12%
激进型：(上限 - 下限) / 下限 = 12-20%
```

**示例**（上限 0.33，不同风格的下限）：

```text
保守型：下限 = 0.33 / 1.08 ≈ 0.306（区间 8%）
均衡型：下限 = 0.33 / 1.12 ≈ 0.295（区间 12%）
激进型：下限 = 0.33 / 1.20 ≈ 0.275（区间 20%）
```

**风险提示**：

- 下限设置过低：价格难以触及，买单长期不成交，错过低价买入机会
- 下限设置过高：价格容易跌破，策略失效，持有大量基础资产面临亏损

### 3.2.6 order_amount（基础订单数量）

**定义**：每个网格层级的基础订单数量（基础资产数量）。

**类型**：Decimal 类型

**代码位置**：

```23:23:scripts/community/fixed_grid.py
order_amount = Decimal(18.0)
```

**配置示例**：

```python
order_amount = Decimal(10.0)    # ENJ 数量
order_amount = Decimal(0.05)    # BTC 数量
order_amount = Decimal(1.0)     # ETH 数量
```

**计算方法**：

1. **基于总资金**

```text
总资金：F
网格层级数：N
平均价格：P_avg = (上限 + 下限) / 2

order_amount = F / (N × P_avg)
```

**示例**（总资金 1000 USDT，8 层网格，均价 0.315）：

```text
order_amount = 1000 / (8 × 0.315) ≈ 397 ENJ

但考虑到需要买卖两侧资金，实际应为：
order_amount = 1000 / (8 × 0.315 × 2) ≈ 198 ENJ

保守起见，设置为：
order_amount = Decimal(150.0)
```

2. **基于风险承受能力**

```text
单层订单占总资金的比例：

保守型：< 5%
均衡型：5-10%
激进型：> 10%
```

**示例**（总资金 1000 USDT，均价 0.315）：

```text
保守型：单层 50 USDT → 50/0.315 ≈ 159 ENJ
均衡型：单层 75 USDT → 75/0.315 ≈ 238 ENJ
激进型：单层 100 USDT → 100/0.315 ≈ 317 ENJ
```

**选择建议**：

1. **考虑交易所最小交易量限制**

大多数交易所对最小订单金额有要求（通常 5-10 USDT）。

```text
order_amount × 网格最低价 ≥ 交易所最小订单金额
```

2. **考虑手续费占比**

```text
单次交易手续费 = order_amount × price × fee_rate

建议手续费占比 < 订单价值的 10%
```

3. **考虑资金利用率**

```text
所需基础资产 ≈ order_amount × N/2
所需报价资产 ≈ order_amount × N/2 × P_avg

总资金需求 ≈ order_amount × N × P_avg
```

**注意事项**：

- 如果启用 `amount_scale_factor`，此参数作为基准值，实际订单数量会按比例缩放
- 订单数量过大可能导致资金不足
- 订单数量过小可能导致利润太少，无法覆盖手续费

## 3.3 可选参数详解

### 3.3.1 spread_scale_factor（网格间距缩放因子）

**定义**：控制网格间距的分布方式。

**类型**：Decimal 类型

**默认值**：1.0（等距网格）

**代码位置**：

```25:25:scripts/community/fixed_grid.py
spread_scale_factor = Decimal(1.0)
```

**取值范围**：

- `1.0`：等距分布（默认）
- `> 1.0`：中间密集，两端稀疏（如 1.1、1.2、1.3）
- `< 1.0`：中间稀疏，两端密集（较少使用）

**配置示例**：

```python
spread_scale_factor = Decimal(1.0)   # 等距，最简单
spread_scale_factor = Decimal(1.2)   # 中间密集
spread_scale_factor = Decimal(1.5)   # 中间很密集
```

**影响示例**（8 层网格，区间 0.30-0.33）：

**等距（factor = 1.0）**：

```text
层 1: 0.3000
层 2: 0.3043  ← 间距 0.0043
层 3: 0.3086  ← 间距 0.0043
层 4: 0.3129  ← 间距 0.0043
层 5: 0.3171  ← 间距 0.0042
层 6: 0.3214  ← 间距 0.0043
层 7: 0.3257  ← 间距 0.0043
层 8: 0.3300  ← 间距 0.0043
```

**中间密集（factor = 1.2）**：

```text
层 1: 0.3000
层 2: 0.3035  ← 间距 0.0035（较大）
层 3: 0.3065  ← 间距 0.0030（中等）
层 4: 0.3090  ← 间距 0.0025（较小）
层 5: 0.3210  ← 间距 0.0120（很小，中心）
层 6: 0.3235  ← 间距 0.0025（较小）
层 7: 0.3265  ← 间距 0.0030（中等）
层 8: 0.3300  ← 间距 0.0035（较大）
```

**使用场景**：

1. **factor = 1.0（等距）**
   - 适合大多数场景
   - 简单易理解
   - 风险均匀分布

2. **factor = 1.1-1.3（轻微缩放）**
   - 价格多数时间在中间区域波动
   - 希望提高中心区域的交易频率
   - 保守型投资者

3. **factor > 1.3（强缩放）**
   - 价格高度集中在某个区域
   - 追求高频交易
   - 需要更高级的市场理解

**风险提示**：

- 缩放因子过大会导致网格分布不均，极端价格保护不足
- 建议首次使用保持 1.0，熟悉策略后再尝试调整

### 3.3.2 amount_scale_factor（订单数量缩放因子）

**定义**：控制不同网格层级的订单数量分布。

**类型**：Decimal 类型

**默认值**：1.0（等量订单）

**代码位置**：

```26:26:scripts/community/fixed_grid.py
amount_scale_factor = Decimal(1.0)
```

**取值范围**：

- `1.0`：每层订单数量相同（默认）
- `> 1.0`：远离中心的订单数量更大（如 1.2、1.3）

**配置示例**：

```python
amount_scale_factor = Decimal(1.0)   # 等量，默认
amount_scale_factor = Decimal(1.2)   # 轻度缩放
amount_scale_factor = Decimal(1.5)   # 强度缩放
```

**影响示例**（8 层网格，基础数量 10）：

**等量（factor = 1.0）**：

```text
层 1: 10 ENJ
层 2: 10 ENJ
层 3: 10 ENJ
层 4: 10 ENJ（中心）
层 5: 10 ENJ
层 6: 10 ENJ
层 7: 10 ENJ
层 8: 10 ENJ
总计: 80 ENJ
```

**缩放（factor = 1.3）**：

```text
层 1: 10 × 1.3³ = 21.97 ENJ
层 2: 10 × 1.3² = 16.90 ENJ
层 3: 10 × 1.3¹ = 13.00 ENJ
层 4: 10 × 1.3⁰ = 10.00 ENJ（中心）
层 5: 10 × 1.3⁰ = 10.00 ENJ
层 6: 10 × 1.3¹ = 13.00 ENJ
层 7: 10 × 1.3² = 16.90 ENJ
层 8: 10 × 1.3³ = 21.97 ENJ
总计: 123.74 ENJ
```

**使用场景**：

1. **factor = 1.0**
   - 标准配置
   - 风险均匀
   - 适合大多数用户

2. **factor = 1.1-1.3**
   - 在极端价格加大投入
   - "抄底"和"逃顶"策略
   - 适合对价格区间有信心的用户

3. **factor > 1.3**
   - 激进策略
   - 需要显著更多资金
   - 风险较高

**风险提示**：

- 缩放因子越大，极端价格的订单越大，若价格突破网格，损失也越大
- 需要更多资金支持
- 建议保守使用

### 3.3.3 rebalance_order_type（再平衡订单类型）

**定义**：库存不足时，再平衡订单的类型。

**类型**：字符串

**默认值**：`"limit"`（限价单）

**代码位置**：

```27:27:scripts/community/fixed_grid.py
rebalance_order_type = "limit"
```

**可选值**：

- `"limit"`：限价单（默认）
- `"market"`：市价单

**配置示例**：

```python
rebalance_order_type = "limit"   # 保守，价格可控
rebalance_order_type = "market"  # 激进，快速成交
```

**对比分析**：

| 类型 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| limit | 价格可控，手续费低 | 可能不成交 | 流动性好的市场 |
| market | 快速成交，保证执行 | 有滑点，手续费高 | 急需再平衡 |

**选择建议**：

1. **使用 limit 的情况**
   - 流动性充足的交易对
   - 不急于恢复网格运行
   - 追求成本控制

2. **使用 market 的情况**
   - 快速波动的市场
   - 需要尽快恢复网格
   - 容忍一定滑点

**示例场景**：

```text
情况：ENJ 价格快速上涨，卖单全部成交，需要买回部分 ENJ

limit 订单：
  - 在当前价格下方 2% 挂买单
  - 等待价格回落成交
  - 风险：价格持续上涨，订单不成交

market 订单：
  - 立即以市场价买入
  - 确保获得 ENJ
  - 成本：可能有 0.5-1% 滑点
```

### 3.3.4 rebalance_order_spread（再平衡订单价差）

**定义**：限价再平衡订单与市场价的偏离比例。

**类型**：Decimal 类型

**默认值**：0.02（2%）

**代码位置**：

```28:28:scripts/community/fixed_grid.py
rebalance_order_spread = Decimal(0.02)
```

**取值范围**：

- 0.01-0.05（1%-5%）较为常见
- 过小：接近市价，成交快但成本高
- 过大：成本低，但可能长时间不成交

**配置示例**：

```python
rebalance_order_spread = Decimal(0.01)  # 1%，激进
rebalance_order_spread = Decimal(0.02)  # 2%，均衡
rebalance_order_spread = Decimal(0.05)  # 5%，保守
```

**计算逻辑**（对应源码第 175、192 行）：

```python
# 买入再平衡
ref_price = 当前市场价
buy_price = ref_price × (100 - spread) / 100

# 示例：市价 0.31，spread = 2%
buy_price = 0.31 × 0.98 = 0.3038

# 卖出再平衡
sell_price = ref_price × (100 + spread) / 100

# 示例：市价 0.31，spread = 2%
sell_price = 0.31 × 1.02 = 0.3162
```

**选择建议**：

1. **根据市场波动性**

```text
低波动（<2%/天）：spread = 0.5-1%
中波动（2-5%/天）：spread = 1-2%
高波动（>5%/天）：spread = 2-5%
```

2. **根据流动性**

```text
高流动性（价差<0.1%）：可用较小 spread
低流动性（价差>0.5%）：需用较大 spread
```

**风险提示**：

- spread 过大可能导致长时间无法再平衡，策略停摆
- spread 过小成本接近市价单，失去限价单优势

### 3.3.5 rebalance_order_refresh_time（再平衡订单刷新时间）

**定义**：再平衡订单未成交时，多久后取消并重新挂单。

**类型**：浮点数（秒）

**默认值**：60.0 秒

**代码位置**：

```29:29:scripts/community/fixed_grid.py
rebalance_order_refresh_time = 60.0
```

**取值范围**：

- 30-300 秒较为常见
- 过短：频繁取消重挂，增加操作成本
- 过长：价格变化后订单价格不合理

**配置示例**：

```python
rebalance_order_refresh_time = 30.0   # 快速刷新
rebalance_order_refresh_time = 60.0   # 默认
rebalance_order_refresh_time = 300.0  # 缓慢刷新
```

**工作原理**：

```text
时间 0s：挂出再平衡买单，价格 0.30
时间 60s：订单未成交，取消订单
时间 61s：获取新市场价（假设涨到 0.31）
时间 62s：挂出新买单，价格 0.31 × 0.98 = 0.3038
时间 122s：再次刷新...
```

**选择建议**：

| 市场状态 | 建议刷新时间 | 理由 |
|---------|------------|------|
| 快速波动 | 30-60 秒 | 价格变化快，需频繁更新 |
| 平稳震荡 | 60-120 秒 | 价格稳定，无需频繁更新 |
| 低波动 | 120-300 秒 | 价格变化慢，减少操作 |

### 3.3.6 grid_orders_refresh_time（网格订单刷新时间）

**定义**：网格订单（正常运行时）多久后取消并重新创建。

**类型**：浮点数（秒）

**默认值**：3600000.0 秒（约 1000 小时，实际上几乎不刷新）

**代码位置**：

```30:30:scripts/community/fixed_grid.py
grid_orders_refresh_time = 3600000.0
```

**说明**：

此参数设置得很大，意味着网格订单在正常情况下几乎不会主动刷新，只在以下情况更新：

1. 订单成交后重新放置新订单
2. 库存再平衡完成后重建网格
3. 手动停止并重启策略

**配置示例**：

```python
grid_orders_refresh_time = 3600.0     # 1 小时刷新
grid_orders_refresh_time = 86400.0    # 1 天刷新
grid_orders_refresh_time = 3600000.0  # 几乎不刷新（默认）
```

**建议**：

- **大多数情况**：保持默认值，无需频繁刷新
- **特殊情况**：如果担心订单长期挂单风险，可设置为 3600-86400 秒

**注意**：频繁刷新会导致：

- 取消订单可能失去成交机会
- 增加 API 调用次数
- 可能增加手续费（部分交易所取消订单也计费）

### 3.3.7 price_source（参考价格类型）

**定义**：用于判断当前市场价的价格类型。

**类型**：PriceType 枚举

**默认值**：`PriceType.MidPrice`（中间价）

**代码位置**：

```31:31:scripts/community/fixed_grid.py
price_source = PriceType.MidPrice
```

**可选值**：

- `PriceType.MidPrice`：买一和卖一的中间价（默认）
- `PriceType.LastTrade`：最新成交价
- `PriceType.BestBid`：最高买价
- `PriceType.BestAsk`：最低卖价

**配置示例**：

```python
price_source = PriceType.MidPrice   # 中间价，最平衡
price_source = PriceType.LastTrade  # 最新成交价
price_source = PriceType.BestBid    # 买一价
price_source = PriceType.BestAsk    # 卖一价
```

**各类型对比**：

| 类型 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| MidPrice | 最平衡，避免偏差 | 实际可能未成交 | 大多数情况（推荐） |
| LastTrade | 真实成交价 | 可能有延迟或异常 | 高流动性市场 |
| BestBid | 保守，容易买入 | 可能偏低 | 做市商策略 |
| BestAsk | 保守，容易卖出 | 可能偏高 | 做市商策略 |

**计算示例**：

```text
当前订单簿：
卖一（BestAsk）：0.3102
买一（BestBid）：0.3098

MidPrice = (0.3102 + 0.3098) / 2 = 0.3100
LastTrade = 0.3099（假设最新成交）
```

**选择建议**：

- **默认使用 MidPrice**：适合 99% 的场景
- 仅在特殊需求时使用其他类型

## 3.4 参数配置最佳实践

### 3.4.1 配置流程

1. **市场分析**
   - 分析目标交易对的历史价格
   - 确定震荡区间（支撑位和阻力位）
   - 计算平均波动率

2. **确定必需参数**
   - 设置交易对和交易所
   - 根据区间设置上下限
   - 根据资金量和区间大小确定层级数和订单数量

3. **调整可选参数**
   - 首次运行保持默认值
   - 运行一段时间后根据表现调优
   - 逐步尝试高级功能（缩放因子等）

4. **测试验证**
   - 小额资金测试
   - 观察订单执行情况
   - 记录收益和风险

5. **持续优化**
   - 根据市场变化调整参数
   - 定期review表现
   - 优化配置

### 3.4.2 配置检查清单

在启动策略前，检查以下项目：

- [ ] 交易对是否正确，交易所是否支持
- [ ] 网格上下限是否合理，当前价格是否在区间内
- [ ] 网格层级数是否为偶数
- [ ] 账户资金是否充足（计算公式见下文）
- [ ] 订单数量是否满足交易所最小要求
- [ ] 手续费率是否了解清楚
- [ ] 是否设置了止损机制

### 3.4.3 资金需求计算

**基础公式**：

```text
平均价格 = (上限 + 下限) / 2
单边资金需求 = order_amount × (n_levels / 2) × 平均价格
总资金需求 = 单边资金需求 × 2 × 1.2（留 20% 缓冲）
```

**示例计算**：

```text
参数：
  - trading_pair: ENJ-USDT
  - grid_price_ceiling: 0.33
  - grid_price_floor: 0.30
  - n_levels: 8
  - order_amount: 100

计算：
  - 平均价格 = (0.33 + 0.30) / 2 = 0.315
  - 单边资金 = 100 × 4 × 0.315 = 126 USDT
  - 总资金需求 = 126 × 2 × 1.2 = 302.4 USDT

建议准备至少 350 USDT
```

## 3.5 本章小结

本章详细讲解了 Fixed Grid 策略的所有 13 个参数：

**必需参数（核心）**：

- `trading_pair`、`exchange`：选择交易对和交易所
- `n_levels`、`grid_price_ceiling`、`grid_price_floor`：定义网格结构
- `order_amount`：确定订单规模

**可选参数（优化）**：

- `spread_scale_factor`、`amount_scale_factor`：高级缩放功能
- `rebalance_*`：再平衡机制配置
- `grid_orders_refresh_time`：订单刷新策略
- `price_source`：价格参考方式

**关键要点**：

1. 首次使用建议保持可选参数为默认值
2. 合理设置网格上下限是成功的关键
3. 确保资金充足，建议预留 20% 缓冲
4. 网格层级数需根据资金量和波动性综合确定
5. 高级功能（缩放因子）需要更深入的理解和更多资金
